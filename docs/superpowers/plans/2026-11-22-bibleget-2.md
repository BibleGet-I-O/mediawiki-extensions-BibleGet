# BibleGet 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the BibleGet MediaWiki extension so that `<biblequote>` and `{{#biblequote:}}` fetch the quote from BibleGet v4 on the server at parse time, with self-registration, a 30-verse cap per tag, failure tracking and in-wiki service notices.

**Architecture:** A parser hook asks a `QuoteFetcher` service for each reference. The fetcher checks the object cache, the per-parse and per-user limits, gets a credential from a `CredentialProvider` (project key, stored installation token, or a fresh registration), calls the API through `BibleGetClient`, and parses the HTML answer with `AnswerParser` into a sanitised, verse-limited `QuoteAnswer`. A `QuoteRenderer` turns that into block or inline markup, or a fallback with tracking categories and a short cache expiry. Service notices in answers go to a `NoticeStore`, then to Echo (or a banner) and `Special:BibleGet`.

**Tech Stack:** PHP 8.1+, MediaWiki 1.43+ (services, HttpRequestFactory, WANObjectCache, abstract schema), Echo (optional), ResourceLoader JS/CSS, PHPUnit and parser tests run in a Docker `mediawiki:1.43` test wiki, Grunt (eslint, stylelint, banana).

**Spec:** `docs/superpowers/specs/2026-11-21-bibleget-2-parse-time-design.md`

## Global Constraints

- MediaWiki >= 1.43; version 2.0.0; license Apache-2.0; manifest_version 2.
- HTTP only through `HttpRequestFactory` (no curl); timeout 5 s.
- API base `$wgBibleGetApiBase`, default `https://query.bibleget.io/v4/`; routes `{base}quote` and `{base}installations`.
- Quote request: POST form fields `query`, `version`, `return=html`; header `X-Api-Key`. No `appid`. The credential is sent in `X-Api-Key` only.
- Registration: POST `{base}installations`, header `X-Api-Key: <client key>`, JSON `{"install_id","plugin_version","site_url"}`; 201/200 → `{"token","installation_id"}`.
- No request ever carries an email address. No `PATCH /installations/self`.
- Credential order: `$wgBibleGetApiKey` if non-null; else stored installation token; else register.
- The key and token never appear in HTML, JS config, API output, logs or exception messages.
- Config keys and defaults: `BibleGetApiBase` (above), `BibleGetApiKey` null, `BibleGetClientKey` (bundled; placeholder `""` until the BibleGet admin mints one), `BibleGetDefaultBibleVersion` `"NABRE"`, `BibleGetCacheExpiry` 2592000, `BibleGetMaxQuotesPerPage` 50, `BibleGetMaxVersesPerQuote` 30.
- Rate limit key `bibleget-fetch`, checked with `User::pingLimiter( 'bibleget-fetch' )` before each uncached fetch; defaults `anon` and `ip` 30 per 60 s, `newbie` 30 per 60 s, `user` 120 per 60 s.
- Right `bibleget-manage`, granted to `sysop`.
- Tracking categories: `bibleget-tracking-category` (failed quotes), `bibleget-toolong-category` (cut to the verse limit).
- Failure: escaped reference + `[!]` marker with a localised reason; tracking category; `ParserOutput::updateCacheExpiry( 3600 )`; negative cache at most 300 s.
- Only the API's `div.results` reaches the page, through an allowlist: elements `div p span br i sup`; attributes `class`, `data-printed-chapter`, `data-verse-label`, `data-omitted`. Editor-written reference text is always escaped.
- Messages in en, qqq, it, es, fr, de, pt; magic words kept for all of them.
- Never call the BibleGet API from a test: tests use a fake `HttpRequestFactory` and the fixtures from Task 2.

## Review Focus

1. Reference text with `<`, `"`, `&`, `{{…}}` or `[[…]]` in the tag body or the function's first argument: shown literally, never parsed as wikitext or HTML (test in Task 6).
2. The same reference twice on one page: one fetch, one cache key, counted once toward `BibleGetMaxQuotesPerPage` (test in Task 6).
3. BibleGet slow or unreachable: the save finishes within the 5 s timeout and the page renders the fallback (test in Task 4 and Task 5).
4. Sub-verses and multi-chapter references (`Mt 5,48-6,2`; verses labelled `5a`, `5b`): the verse limit counts each verse once and cuts after the 30th, across chapters (test in Task 3).
5. An anonymous user over the rate limit previews a page whose quotes are all cached: every quote renders; only uncached ones fall back (test in Task 5).
